# Hi-Introvert UI v1.2 — Design

**Date:** 2026-05-23
**Status:** Approved scope, awaiting spec review

## Goal

Replace the current blessed-based TUI with a minimal, Gemini/Claude-CLI-style chat UI built on Ink. Surface a thin layer of "ambient telemetry" so the user can feel the companion is alive (skills, env, battery) without cluttering the chat.

## Decisions (locked)

| Topic | Choice |
|---|---|
| Framework | **Ink v5** (rebuild). Delete blessed entirely. |
| Layout | Header (logo + tips) → Chat → Status row → Input → Footer |
| Color | Emotion-tinted companion text; bright user input; subtle (not dim) footer |
| Ambient telemetry | Skills row + env summary + battery indicator |
| Rejected | Inline event indicators, mood-driven gradient, debug panel |

## Components

- **`<Banner>`** — gradient ASCII logo + tips (renders once at startup, then unmounts to save vertical space)
- **`<ChatView>`** — message list, auto-scroll, sender-colored
- **`<StatusRow>`** — 2-line summary: vocab+skills, env+weather
- **`<InputBox>`** — bordered prompt with `>` prefix
- **`<Footer>`** — cwd, battery, version

## Data wiring

| UI element | Source | Update trigger |
|---|---|---|
| Companion color | `companion.emotion.valence/arousal` | After each response |
| Skills row | `companion.skills.getProficiency(name)` | On `skills-initialized` + every reply |
| Env row | `session.environment.getState()` + `session.weather.getState()` | Subscribe to `environment` + `weather` events |
| Battery | `session.osSensor.getMetrics().batteryLevel` | Subscribe to `environment` event (which carries metrics) |

Three previously-unconsumed events get listened to: `environment`, `weather`, `skills-initialized`. The other 10 unused events stay unused for now (out of scope per "thin layer" decision).

## External ambient sources (new, v1.2)

Goal: make companion feel "เพื่อนในคอมจริงๆ" by letting entity perceive 3 external signals without ever turning the UI into a dashboard. **Ambient vibe, not Hakerman.**

Pattern: each source = small class that calls `world.broadcastEvent(type, payload)` on an interval. Entity receives via inbox, samples ~10-20% to `remember()` with low-medium salience, then organically surfaces these in proto-lang or self_monologue. No hard-coded dialogue lines about moon/weather/cwd.

### Sensors

| Sensor | Interval | Event type | Payload | Network |
|---|---|---|---|---|
| `MoonSensor` | 1h | `lunar_phase` | `{ phase: 0..1, name: 'waning_crescent', illumination: 0.3 }` | none (formula) |
| `LocalContextSensor` | 30s | `local_context` | `{ cwdName, recentFileAge, foregroundApp? }` (macOS osascript opt-in) | none |
| `OutsideWeatherSensor` | 10min | `outside_weather` | `{ description, tempC, condition }` from wttr.in | yes, silent fail |

### UX rules (the "ambient" contract)

- **No numeric fields in main UI** — no "moon: 30%", no "wind: 12 km/h"
- **/status** may show a subtle 1-line echo: `companion senses: 🌙 waning crescent · 🌧 light rain · 📁 in projects/hi-introvert`
- Sensors fail **silently**: wttr.in offline = sensor disabled, no error to user
- First-launch consent: a tiny line in Banner: "wttr.in fetches your local weather. /privacy to disable."
- `/privacy` command (new) → toggles `OutsideWeatherSensor` + `LocalContextSensor` on/off, persisted to session

### Sampling guidance

To prevent inbox spam (10 events / minute = 600/hr per entity):
- Moon: salience 0.5 (rare but memorable)
- Weather: salience 0.3 (frequent but ambient)
- Local context: salience 0.1 (background hum)

Entity's `remember()` sample rate stays at 10% — already in code at [WorldSession.ts:400](src/session/WorldSession.ts:400).

## Out of scope (explicitly)

- Inline event indicators ("thinking...", "raining...")
- Mood-driven gradient color
- Debug panel toggle
- The 10 unconsumed events (`cognitive-link`, `memory-sync`, `crystallization`, etc.)
- Multi-language UI labels (English UI chrome only; Thai/EN content via companion)
- Tier B/C external sources (ISS, USGS, NOAA, macOS Music, Calendar, GitHub)
- Hard-coded weather/moon dialogue lines in MDM (emergent only — let proto-lang surface them)

## Risk: stdin.setRawMode bug

Previous comment claimed Ink had this bug. With Ink v5 + Bun 1.2 + Node 22, this is no longer reported. If reproduced, fallback is `process.stdin.setRawMode = () => {}` shim before `render()` — known workaround.

## Success criteria

- `bun run dev` launches the Ink UI
- `/help` lists 9 commands from `HELP_TEXT` (no drift from existing tests)
- Companion mood reflects in text color visibly
- env line updates within 10s of system load change
- All 42 existing tests still pass (no regressions in tokenizer / dedupe / commands)
- New components have at minimum smoke tests (renders without crash)
- Each new sensor has a pure-function test (no real network for OutsideWeatherSensor — inject fetcher)
- Companion organically references moon/weather/cwd at least once per ~20 messages in manual smoke run (qualitative)
- `/privacy` toggle persists across save/load
